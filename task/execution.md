# 任务执行监控与结果解析 (Task Execution & Results)

当工作流下发出具体的任务单 (`Task`) 至 Go 扫描节点后，安全工程师可通过 **任务执行详情查看**、**ANSI 实时彩色终端日志 (`LogViewer`)** 以及 **7 大结果结构化解析流水线 (`OutputParser`)** 对任务进行监控与输出处理。

---

## 一、 任务详情与节点状态监控

在 **「任务管理」->「任务列表」** 中点击任意条目的 **「详情」**，将展开该底层探针任务的核心生命周期状态：

### 1. 任务状态机流转 (`TaskStateMachine`)
底层任务引擎严格遵循状态机控制规范，保证分布式并发环境下的幂等性与可靠性：
- ⏳ **PENDING (待派发)**：工作流拆解生成的任务已入库，等待匹配在线的 Go 扫描节点。
- 📌 **ASSIGNED (已分配)**：任务已被某台扫描节点领取（通过长轮询或 WebSocket 拿取信封）。
- 🔄 **RUNNING (执行中)**：节点已启动 Docker 容器或本地进程，并持续上传实时日志。
- ✅ **COMPLETED (已完成)**：命令正常返回 `ExitCode 0`，且输出数据已通过 `OutputParser` 成功解析入库。
- ❌ **FAILED (执行失败)**：底层命令返回非零退出码、资源超限、网络超时或解析异常。
- ⏭️ **SKIPPED (已跳过)**：由于上游依赖节点无输出数据，或条件表达式（`condition`）判定为 `false` 而自动跳过。

### 2. 心跳与熔断重试机制
- **节点心跳检测**：后端持续监控探针的心跳时间。若节点在执行过程中因断网、掉电或崩溃超过心跳阈值，系统会自动将关联任务重置或阻断。
- **自动重试策略**：若工作流配置了 `maxRetries`（如 `2` 次），对于网络瞬时波动或超时失败的任务，`TaskStateMachine` 会自动将其重新置为 `PENDING` 重新排队调度。

### 3. 人工干预与生命周期控制
- **强行终止 (Kill)**：对于卡死或占用过多 CPU/内存的 `RUNNING` 任务，管理员可点击 **「强行终止 (Kill)」**，服务端将立即向节点下发强退信号并清理关联 Docker 容器。
- **单任务重试 (Retry)**：对于排查修复环境后的失败任务，支持在列表页点击 **「重试」** 进行单节点重新调度。

## 二、 实时 ANSI 彩色终端日志 (LogViewer)

无需 SSH 登录到远程探针节点，TestNet 的 **实时日志查看器 (LogViewer)** 可为您提供流畅的终端级观测体验：

### 1. 实时流式推送
- 扫描节点在执行底层命令或容器任务的过程中，实时捕获标准输出和标准错误，并不间断传输至服务端；
- 平台经过低延迟安全通道将原生日志流实时推送至控制台界面。

### 2. 彩色样式完美渲染与关键字检索
- 系统自动将控制台原生彩色控制符（如高危红、提示黄、调试绿）转换为带高亮样式的网页文本；
- **内置搜索与过滤**：日志面板顶部提供关键字检索框与 `Error/Warning` 级别快速筛选开关，在数十万行爆破日志中一秒定位核心报错记录。

## 三、 7 大结果结构化解析流水线

各类安全扫描工具输出的原始结果千差万别（如 JSON 行、正则文本、CSV 表格等）。为了让原生命令行输出能够直接入库并生成标准的资产实体，TestNet 构建了强大的 7 大结构化解析流水线：

| 解析引擎 | 标识符 | 适用工具与输入特征 | 核心解析机制 |
| :--- | :--- | :--- | :--- |
| **JSON 解析器** | `JSON` | 整体输出为一个完整的 JSON 对象或数组的文件 | 将 JSON 对象直接反序列化并自动映射为资产属性入库 |
| **JSON Lines 解析器** | `JSONL` | 每一行都是一个独立的 JSON 对象 (如 `subfinder`, `httpx`, `nuclei`) | 逐行流式解析，超低内存开销，适合数十万行并发扫描结果的极速抽取 |
| **CSV 表格解析器** | `CSV` | 标准逗号分隔或制表符分隔表格 | 依据表头字段映射 (`Header Mapping`) 自动对应资产模型的属性 |
| **正则表达式解析器** | `REGEX` | 传统命令行工具的纯文本输出 (如部分原生 `nmap`, `banner` 抓取) | 使用捕获组 (`Capture Groups`) 提取 IP、端口号、版本及具体漏洞编号 |
| **XML 文档解析器** | `XML` | 传统扫描仪 (如 `Nmap XML`, `Nessus XML`) | 使用 XPath 或 XML 解析引擎精确提取嵌套节点中的资产细节与漏洞报告 |
| **行级文本解析器** | `LINE` | 纯域名列表、IP 列表、目录爆破路径文件 | 将每行文本去除前后空格直接作为独立实体字段（如主域名下的子域字符串） |
| **复合流水线** | `PIPELINE` | 经过多重处理链的特殊产物 | 组合调用上述多个解析引擎，例如先对大文本进行正则过滤，再把提取块送入 JSONL 解析 |

> [!NOTE]
> 解析通过的数据将进行智能分流与入库：属于新增子域名/IP/Web站点的直接保存至 **资产中台**；属于漏洞告警 (`PoC`) 的直接生成 **漏洞记录** 并触发平台的即时通知。
