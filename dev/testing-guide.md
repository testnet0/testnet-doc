# AI 浏览器自动化全量验收手册

> 适用场景: AI 调用浏览器自动化工具执行 TestNet 发布前全量端到端验收

## 一、测试目标

本手册用于指导 AI 浏览器自动化完成 TestNet 平台全量验收，覆盖从本地环境启动、系统激活、登录、业务模块验证到最终报告生成的完整流程。

验收目标：

- 验证本地开发环境可以完整启动
- 验证系统激活、登录、会话保持和退出流程可用
- 验证 Dashboard、项目、资产、资产配置、搜索、工作流、工具、配置文件、节点、任务、通知、系统管理等核心页面可正常访问
- 验证项目和 8 类资产的增删改查、搜索、分页、导入导出和关联关系
- 验证常见异常场景下页面不白屏、提示清晰、权限跳转正确
- 生成可追溯的测试报告

## 二、测试范围

### 2.1 必测模块

| 模块 | 路由 | 验收重点 |
|------|------|----------|
| 系统激活 | `/login` | 机器码展示、授权内容提交、激活成功或跳过记录 |
| 登录 | `/login` | 默认账号登录、会话保持、退出登录、错误密码提示 |
| Dashboard | `/dashboard` | 统计卡片、图表、通知、项目切换、WebSocket 状态 |
| 项目管理 | `/project` | 新增、查询、编辑、删除、搜索、分页 |
| 8 类资产 | `/asset/*` | CRUD、关联关系、导入导出 |
| 资产配置 | `/asset/config/*` | 标签、规则、根域名、通知、漏洞类型、历史清理 |
| 搜索引擎 | `/search` | 配置、语法配置、查询、导入资产 |
| 工作流 | `/workflow` | 列表、编辑器、校验、执行、运行记录 |
| 工具管理 | `/tool` | CRUD、校验、复制、导入 YAML、商店安装 |
| 配置文件 | `/config-file` | CRUD、版本内容保存 |
| 扫描节点 | `/client` | 节点列表、状态、心跳 |
| 任务管理 | `/task` | 列表、详情、日志、执行结果 |
| 通知中心 | `/notification` | 未读数、标记已读、删除 |
| 系统管理 | `/system/*` | 用户、角色、部门、权限、配置 |

### 2.2 可跳过模块

以下模块依赖外部环境，无法满足条件时记录为 `SKIPPED`：

- 系统激活：已激活或关闭授权时跳过
- 搜索引擎查询：无外部密钥时仅验证配置页面和错误提示
- DSL 商店：未配置商店时仅验证按钮能唤起抽屉
- 扫描节点执行：本地未启动 client 时仅验证空状态
- 工作流真实执行：无可用节点时仅验证校验和错误提示

## 三、本地环境启动

### 3.1 前置要求

| 依赖 | 要求 |
|------|------|
| Docker | 可运行 Docker Compose |
| Java | JDK 17 |
| Maven | 3.8+ |
| Node.js | LTS 版本 |
| Go | 1.21+（验证扫描节点时需要） |

### 3.2 启动 PostgreSQL 和 Redis

```bash
docker compose -f docker-compose-dev.yml up -d
```

验证项：PostgreSQL 监听 `127.0.0.1:5432`，Redis 监听 `127.0.0.1:6379`。

### 3.3 启动后端

```bash
cd testnet-server
mvn spring-boot:run
```

验证项：后端监听 `http://127.0.0.1:8081`，Flyway migration 完成，无连接错误。

### 3.4 启动前端

```bash
cd testnet-web
npm install && npm run dev
```

验证项：前端监听 `http://127.0.0.1:3100`，浏览器打开 `/login` 不白屏。

### 3.5 启动扫描节点（可选）

```bash
cd testnet-client
go run ./cmd -server http://localhost:8081 -secret dev-client-secret-for-local-testing -name AI-E2E-Node
```

验证项：节点注册成功，`/client` 页面可见 `AI-E2E-Node`。

## 五、AI 浏览器自动化执行约定

### 5.1 操作原则

- 优先通过可见文本、按钮名称、表单 label 定位元素
- 不依赖易变 CSS class
- 每进入一个模块先等待主标题或表格出现
- 每次提交后等待成功消息再执行下一步
- 每个模块至少保存一张截图
- 每个失败用例必须保存截图、URL、控制台错误

### 5.2 通用断言

每个页面都应验证：

- 页面 URL 与预期路由一致
- 页面无白屏
- 主标题或核心功能区可见
- 无未授权跳转（除权限测试用例外）
- 控制台无严重错误
- 网络请求无非预期 401/403/500

### 5.3 证据采集路径

## 六、前置健康检查

1. 打开 `http://127.0.0.1:3100/login`，等待页面渲染
2. 检查登录页或激活页可见，无白屏
3. 确认 `/api` 代理请求可达后端

## 七、系统激活验收

### 7.1 未激活场景

1. 若页面显示"系统激活"，读取并复制机器码
2. 粘贴授权文件内容，点击"立即完成激活"
3. 验证机器码不为空，激活成功后切换到"用户登录"

### 7.2 已激活或关闭授权场景

记录为 `SKIPPED`，不影响后续测试。

## 八、登录与会话验收

### 8.1 正确账号登录

输入 `admin / 123456`，验证跳转到 `/dashboard`，token 存在于 localStorage。

### 8.2 错误密码

输入 `admin / wrong-password`，验证停留在 `/login` 并出现错误提示。

### 8.3 会话保持与退出

刷新页面确认会话保持；退出后 token 清除，未登录访问跳转 `/login`。

## 九、Dashboard 验收

验证统计卡片、图表、通知铃铛、WebSocket 状态展示，无非预期错误。

## 十、项目管理验收

新增项目 `AI-E2E-项目-<timestamp>` → 查询 → 编辑 → 删除，验证 CRUD 流程。

## 十一、资产管理全量验收

### 11.1 通用 CRUD 流程

适用于 8 类资产页面：新增 → 搜索 → 编辑 → 删除，验证必填校验、保存、更新、删除、分页、导入导出入口。

### 11.2 ~ 11.9 各资产类型

按顺序验证：公司 → 主域名 → 子域名 → IP → 端口 → Web → API → 漏洞的 CRUD 和关联字段。

## 十二、资产关联关系验收

### 12.1 正向链路验证

按 `Project → Company → Domain → Subdomain → IP → Port → Web → API → Vul` 顺序创建关联，验证各关联字段可保存。

### 12.2 关联持久化验证

每个关联保存后刷新页面，重新打开编辑弹窗检查关联字段不丢失。

### 12.3 删除顺序验证

按依赖倒序 `Vul → API → Web → Port → IP → Subdomain → Domain → Company → Project` 清理。

::: warning 删除顺序
必须按依赖倒序删除测试数据，不得删除非 `AI-E2E-<timestamp>` 数据。
:::

## 十三、资产导入导出验收

导出 8 类资产 Excel 文件；导入含 `AI-E2E-IMPORT-<timestamp>` 数据的 Excel；上传错误文件验证清晰提示。

## 十四、资产配置验收

验证标签配置、自动标签规则、归属规则、根域名配置、访问规则、通知规则、漏洞类型配置、历史清理配置。

## 十五、搜索引擎验收

配置引擎 → 配置语法 → 执行搜索 → 导入资产；无密钥时验证错误提示不白屏。

## 十六、工作流验收

列表 CRUD → 编辑器 DAG → 校验 → 执行 → 运行记录 → 从商店导入。

## 十七、工具管理验收

列表 CRUD → 校验 → 复制 → 导入 YAML → 从商店安装 → 预览目标解析。

## 十八、配置文件管理验收

CRUD → 内容保存不丢失 → 删除后不可查询。

## 十九、扫描节点验收

空状态展示正常；启动本地节点后验证名称、状态、心跳。

## 二十、任务管理验收

列表 → 详情 → 日志 → 结果；失败任务有错误信息，成功任务有输出摘要。

## 二十一、通知中心验收

未读数 → 标记已读 → 全部已读 → 删除 → 铃铛同步更新。

## 二十二、系统管理验收

- 用户管理：新增、编辑、禁用/启用、分配角色、删除（不删 admin）
- 角色管理：新增、编辑、分配权限、删除
- 部门管理：新增、编辑、删除
- 权限管理：列表展示、权限树、搜索
- 系统配置：编辑非敏感配置、测试连接
- 个人资料：查看、修改非关键字段
- 授权管理：查看状态、机器码、激活

## 二十三、权限与异常页面验收

- 未登录访问 `/dashboard` → 跳转 `/login`
- 低权限用户访问无权限路由 → 跳转 `/403`
- 不存在路由 → 不白屏
- 表单异常：必填空提交、重复唯一字段、错误格式、取消删除

## 二十四、数据清理

只清理 `AI-E2E-<timestamp>` 数据，按依赖倒序删除，不删系统内置数据。

## 二十五、测试报告

### 25.1 汇总报告 (`summary.md`)

包含环境信息、各模块结果统计、资产链路验证、导入导出结果、最终结论。

### 25.2 模块独立报告 (`report_<module>.md`)

每个模块独立报告包含：模块信息、用例结果表、失败详情、跳过项、控制台异常、清理确认。

### 25.3 通过标准

- 环境启动、登录、Dashboard、项目管理、资产管理、资产关联必须通过
- 8 类资产 CRUD 至少全部通过一次
- 导出覆盖 8 类资产，导入至少覆盖 5 类
- 系统管理无阻塞问题
- 非外部依赖模块无白屏、无非预期 401/403/500
- 所有失败有截图和复现步骤
- 测试数据清理完成或残留已记录

## 二十六、推荐执行顺序

1. 启动环境 → 健康检查
2. 系统激活或记录跳过
3. 登录 → Dashboard
4. 创建项目 → 创建完整资产链
5. 验证关联持久化
6. 搜索、编辑、导出、导入
7. 资产配置 → 搜索引擎
8. 工具、工作流、配置文件
9. 扫描节点（或跳过）→ 任务 → 通知
10. 系统管理 → 权限与异常场景
11. 按倒序清理数据
12. 生成各模块报告和汇总报告
